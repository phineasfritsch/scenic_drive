corpus activation (nearest within 25 m), mark needs re-plan if unresolved; replay = one /plan with the saved waypoints at

the replay call are later tasks. Linux-only target: Foundation + GRDB, never CoreLocation. Swift is native on this box
(memory swift-native-on-windows-box): `swift test --scratch-path .build/<own-id>`.

A Double v has at most 5 dp iff v is finite and `Double(k) / 1e5 == v` for `k = (v * 1e5).rounded()` - v is the double nearest the decimal k/100000 - and is stored as k. Refusals are typed `SavedDriveError` cases per field: latitude/longitude `notFinite`, `outOfRange`, `moreThanFiveDecimals`; lambda `notFinite`, `negative`, `moreThanFiveDecimals`.   - R5 RE-RESOLVE. `SavedDriveResolver.resolve(_:against:)` is the rule; it uses nothing from GRDB, so its table and the mutation population run natively. The SHIPPED entry point on corpus activation is `SavedDriveStore.reresolve(against:)`, which runs it over every stored drive and writes each result; the same table runs through it in the GRDB suite. The corpus is a `SavedDriveCorpus` (`segment(id:)`, `segmentIDs(in:)`), which PlaceStore conforms to with its existing methods; BoundingBox leaves the GRDB gate (a plain value, as T-0255 R5 did for Segment). For each saved segment: id present -> kept. Absent -> candidates = `segmentIDs(in:)` a box around the saved midpoint (half-side twice the 25 m angle; longitude widened by 1/cos(lat), the whole longitude range when cos(lat) < 0.01), distance = haversine (R = 6_371_008.8 m) from the saved midpoint to each candidate's stored mid_lat_e7/mid_lon_e7; the nearest with distance <= 25 m wins, ties to the lowest id. All absent ids replaced -> new ids, needsReplan false. Any absent id with no candidate -> the drive keeps ALL its old ids, needsReplan true. Midpoints are never rewritten (they are the drive's record of where it went; rewriting would round and drift across corpora). A replacement may repeat another saved id (two old segments merged by re-segmentation) and is not de-duplicated. Empty drive -> unchanged, needsReplan false. needsReplan is a function of (saved ids, current corpus): a later corpus that resolves every id clears it.
